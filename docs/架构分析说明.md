## 一、架构总体概述

本系统采用 **大模型内核 + LangChain 工程框架 + 多智能体协作 + RAG 知识检索 + FastAPI 服务化部署** 的五层企业级大模型应用架构。

整体以 Anthropic Claude 系列模型为智能推理核心，依托 LangChain 实现 LLM 能力工程化、流程化、组件化落地，解决传统大模型应用**上下文有限、无法联网、无记忆、输出不可控、不可扩展**的问题，最终构建一套可稳定运行、可迭代扩展、可服务化调用的竞品智能分析系统。

架构遵循 **模型解耦、业务插件化、数据时序化、服务标准化** 的设计思想，实现从原始舆情数据采集、语义解析、多智能体分工分析、向量知识库检索、结构化对比推理到最终简报生成的完整大模型应用链路。

```
┌─────────────────────────────────────────────────────────┐
│  5. 服务化部署层   FastAPI + Docker + LangSmith          │
├─────────────────────────────────────────────────────────┤
│  4. 向量数据持久层   Claude Embeddings + Chroma          │
├─────────────────────────────────────────────────────────┤
│  3. Multi-Agent 层   插件化抽象基类 + 注册表 + 3 Agent    │
├─────────────────────────────────────────────────────────┤
│  2. LangChain 框架层  LCEL / RAG / Memory / OutputParser  │
├─────────────────────────────────────────────────────────┤
│  1. 大模型基础层     Claude Haiku / Sonnet / Opus         │
└─────────────────────────────────────────────────────────┘
```

## 二、五层技术架构详解

### 1. 大模型基础层
本项目选用 Anthropic Claude 模型体系作为唯一推理底座，根据业务场景实现**模型分层调用策略**，兼顾速度、成本与推理深度：

| 模型 | 适用场景 | 特点 |
|------|---------|------|
| **Claude Haiku** | 高速舆情抓取、文本清洗、关键词提取、轻量分类 | 大批量数据处理效率优先 |
| **Claude Sonnet** | 核心结构化分析、竞品维度对比、数据规整、工具调用解析 | 性能与精度平衡 |
| **Claude Opus** | 复杂竞争推理、战略研判、最终报告生成、机会与威胁深度分析 | 高阶业务洞察 |

通过 **Prompt Engineering、FewShot 示例注入、结构化输出约束**，强制模型输出标准化 JSON / 表格格式，解决大模型输出自由、不可用于业务系统的问题。

> 对应代码：`modules/llm_client.py`（LLMClient 分层适配器）、`modules/prompts.py`（JSON_OUTPUT_GUARD）

### 2. LangChain 工程框架层（核心调度层）
LangChain 是本项目核心工程骨架，负责将原生 Claude 大模型能力组装为可落地的业务流程：

- **Chain 链路编排**：基于 LCEL 声明式语法，搭建「舆情加载 → 文本分割 → 向量化检索 → LLM 分析 → 结构化输出」的多步固定业务流水线；
- **RAG 检索增强生成**：通过 Document Loader 加载多源舆情、TextSplitter 语义分块、Embeddings 向量化、Chroma 向量库检索，让模型基于真实最新竞品数据回答，摆脱训练数据陈旧问题；
- **Memory 上下文记忆**：持久化保存竞品分析历史会话，实现增量对比、时序追踪、连续分析；
- **OutputParser 结构化约束**：强制模型输出固定字段的结构化数据，为前端图表、对标表格、报告渲染提供标准化数据源。

> 对应代码：`modules/rag_chain.py`（LCEL 链路：retriever | prompt | llm | parser）

### 3. Multi-Agent 多智能体插件层（业务核心）
项目采用**自研抽象 Agent 插件化架构**，基于面向接口编程思想实现系统高扩展性：

- 定义统一抽象基类 `AbstractAgent`，通过抽象属性 `name` 强制每个智能体拥有全局唯一标识；
- 实现全局 Agent 注册表 `AgentRegistry`，通过装饰器自动完成插件注册、统一管理、动态调度；
- 拆分出**价格监控、新品迭代、负面舆情**三类独立智能体，各司其职并行完成多维竞品分析；
- 新增分析维度只需新增 Agent 插件，无需修改核心调度代码，实现模块热插拔；
- 基于 Claude Function Calling 实现工具调用能力，让 Agent 自主选择检索、对比、总结等工具，模拟真实分析师思考步骤。

> 对应代码：`modules/agent_core.py`、`modules/tools.py`

### 4. 向量数据持久层（时序对比核心）
采用 Embeddings + Chroma 向量数据库构建竞品时序知识库：

- 所有历史舆情、竞品动态、对标记录全部向量化存储；
- 支持按**竞品、按维度、按时间段**检索历史数据；
- 支撑系统长期时序对比、趋势分析、变化追踪，实现普通大模型无法完成的纵向深度研判。

> 对应代码：`modules/rag_chain.py`（持久化目录 `chroma_db/`）

### 5. 服务化部署层（工程落地）
- 通过 **FastAPI** 将 LangChain 智能分析链路封装为标准 RESTful API，实现前后端分离、异步流式输出、高并发接口调用；
- 通过 **Docker** 容器化打包，支持云端一键部署；
- 配合 **LangSmith** 实现全链路追踪、调试与性能监控。

> 对应代码：`modules/api_server.py`

## 三、整体技术架构优势

| 优势 | 说明 |
|------|------|
| 智能分层 | 不同复杂度任务匹配不同 Claude 模型，效率高、成本可控 |
| 工程标准化 | LangChain 组件化编排，流程清晰、可维护、可迭代 |
| 业务解耦 | 插件化 Agent 架构，业务模块可自由扩展、插拔替换 |
| 数据可持续沉淀 | 向量知识库持续积累竞品数据，越用越精准 |
| 可直接企业落地 | 完整具备 API 服务、容器部署、链路监控等生产级能力 |
